## 1. What this is

termocab is an open-source, terminal-native language-learning CLI. Tagline: **"Language learning for terminal enthusiasts."**

Non-negotiable philosophy:
- Runs entirely in the terminal. No GUI, no browser, no server, no network dependency. Fully offline, fully local.
- Fast, lightweight, keyboard-driven.
- No ads, no mandatory account, respects user data.
- UX modeled on real Unix tools — **git** is the explicit style reference: clear, direct subcommands. No interactive menus, no numbered prompts waiting for input. Every command is a complete, self-contained verb: `termocab <subcommand> [args]`.

Name history: `ling` → `vex-lang` → `tvocab` → **`termocab`** (current, final). An earlier, broader `vex-lang` vision doc described a full TUI + detailed SRS system — that is a long-term reference only, **not** current MVP scope.

The **twelfth-language session (Nov 2026)** shipped Catalan as the twelfth course and **the fifth engine change a language has forced (D18)** — the smallest table yet, and the first entry that is not a letter: one character, the interpunct. D9 named Catalan in its coverage list the day it widened the accent table to the whole Latin-1 Supplement, and the language arrived to collect almost everything — à è é í ï ó ò ú ç all ride the Latin-1 `ACCENTED` entries (the very ç French shipped with), every one alive in real content (gràcies, què, sí, raïm, és in the sentences, mòbil in a sentence, adéu, núvol, pingüí in a sentence, feliç) — leaving exactly the question the roadmap had held open for it: is the raised dot decoration like ¡ ¿, or meaningful like a letter? D18's answer: neither. Not decoration — ¡ and ¿ only ever wrap an utterance and carry nothing inside the word, while the interpunct sits *inside* the word and its absence is a genuine misspelling (`collegi` is wrong in Catalan; the IEC norm requires the punt volat between certain geminates), so stripping it in the strict pass would hand a full match to a misspelled answer. Not a letter in its own right — it has no sound and no place in the alphabet, unlike the closed club ø þ ð ı whose members are phonemes with their own slot; it separates `l·l` from `ll`, a spelling convention rather than a phoneme. It takes the tier ł built (D10): a new one-entry table, `FOLDED_MARKS` — marks that fold away in the loose pass without being combining diacritics — so the dot survives the strict pass (`col·legi` typed right is a full match) and folds in the loose one: `collegi` counts with `col·legi` as the hint, exactly like `lodz` counts with `łódź`. Two edges pinned as documented behavior: the ASCII hyphen some typists fall back to (`col-legi`) stays a miss — folding internal hyphens would touch every course that ships one, and the change is deliberately additive only (the D14 rule: no other shipped course contains the character) — and ŀ (U+0140, l + middle dot), which canonically decomposes to l + ·, lives in no modern text — the Portuguese â rule, one tier stricter — so it stays off `ACCENTED`. The course is standard (IEC) Catalan as spoken in Catalonia, the second explicit variant decision after D12's Brazilian Portuguese (tu-forms, `si us plau`, `Gràcies. — De res.`, pa amb tomàquet on the food stage). Nouns carry their gendered articles like the Portuguese course's, with the Catalan twist the article convention gains: the apostrophe elision — l'home, l'amic, l'aigua, l'hora, l'habitació, l'esmorzar, l'estiu, l'hivern, l'any passat, l'autobús, l'hotel, l'hospital — alive in vocabulary and sentences the way the German course carries its capitalization, not drilled; stage 3's signature is the mandatory contraction pair, the crase's sister (`Vaig ___ mercat` wants al, `Vinc ___ treball` wants del — a + el and de + el are fused by grammar in a way even Spanish's are not); stage 4 keeps the modal drill, voler/poder + the bare infinitive, with ser/estar contrasted across the sentences (`Sóc de Barcelona` against `Estic a casa ara`); stage 6 drills the agradar flip beside the tenir idioms (tinc gana, tinc set); stage 7's existential hi ha takes the slot Portuguese gave tem, the locative contractions returning on new vocabulary; stage 8's reflexive clitics (`Jo ___ llevo a les set` wants em) mirror the Portuguese me/se/nos levanto drill, weather beside them; stage 9 is the price drill (`Quant ___ el cafè?` wants costa, les pomes want costen) on the twenties and a sums ladder; stage 10 is the go-past — anar + infinitive grammaticalized into the simple past (`Ahir ___ menjar pizza` wants vaig), drilled against the go-future in a minimal pair (`Demà ___ a treballar` wants vaig again — the tense carried by ahir/demà and the a), with `vam anar a Roma` showing the go-verb carrying its own past. `accepted_translations` carries the genuine homonyms: el temps is weather and time, el col·legi is school and college (the false friend, the Icelandic banki pattern), la pel·lícula film/movie, la tardor autumn/fall, la feina work/job, l'hora hour/time. Every Catalan letter is alive in real content (à in gràcies and fàcil, è in què and per què, é in és, í in sí and difícil, ï in raïm, ó in sóc, ò in el mòbil — a sentence — ú in adéu and núvol, ü in el pingüí — a sentence, ç in feliç and març, and · in col·legi and pel·lícula, both vocabulary). With the ligatures — it is one (the Unicode name says so), and its opening is the two-letter sequence it spells (ĳ → "ij"), the œ → oe and æ → ae shape, while `OPEN_LETTERS` holds letters in their own right opening to a single plain letter (ł → l), which ĳ is not: it has no phoneme of its own, it is typography for the ij digraph the language writes with two letters everywhere. `LIGATURES` grew to four (œ æ ß ĳ); `OPEN_LETTERS` still holds just ł; the closed club ø þ ð ı gains nothing, and the change is purely additive (the D14 rule). The strict pass leaves ĳ alone (the ligature's decomposition is compatibility, not canonical, so it cannot ride `ACCENTED`'s strict machinery — a correctly ligatured `ĳsselmeer` is a full match) and the loose pass opens it: `het IJsselmeer` — what every modern text types — counts with `het Ĳsselmeer` as the hint, the ß/straße tier, and the old-orthography spelling folds in reverse (`mĳn` for `mijn`); the schoolbook y is no spelling of any word, so `myn` is wrong for `mijn`, never hinted — the same counterweight the Catalan hyphen and the closed letters carry. Capital Ĳ needs no entry and no authoring rule: `to_lowercase` maps it to ĳ (single char, no D15-style residue), so an all-caps answer grades strict with no hint at all. ## 3. Architecture — read this before writing any code

Strict layered separation:

```
Terminal/CLI  →  Application Logic  →  Learning Engine  →  Progress Tracker  →  Storage Layer
                                    ↘ SRS Scheduler ↗
```

**The single most important rule in this codebase:** `engine/`, `progress/` and `srs/` must never know how anything is stored. No JSON, no file I/O, no SQLite — ever. They only work with plain in-memory types. `content/` and `storage/` are the only modules allowed to know both about the domain types and about a storage format at the same time; they convert between the two. This is what lets the project move from JSON/plain-text to SQLite later by rewriting only the storage-facing modules.

`session/` is the application layer: it knows `engine::`, `progress::` and `srs::` but not files or dates. `cli/` is the only module that touches `std::env`, exit codes, and "what day is it" (the storage layer takes the config root as a parameter; `cli/` resolves `$XDG_CONFIG_HOME`/`$HOME` and hands it in). The `Terminal` trait in `session/` abstracts stdin/stdout so tests drive the runner with scripted answers, and `read_line` returns an `Input` enum so EOF and unreadable input are distinct.

`src/lang.rs` is a deliberate leaf addition to this picture: a tiny shared `LangId` newtype (validated `[a-z0-9_-]{1,32}`) that `cli/`, `content/` and `storage/` all use so an unvalidated language name can never reach a file path. It depends on nothing, so it adds no coupling between layers.

`srs/` is deliberately the same kind of module as `progress/` — a pure domain layer sitting beside it, not under it: it never reads `LanguageProgress`, it just receives "these words, this date" from the caller. Which words qualify (vocabulary of completed stages) is decided in `cli/`, where content and progress meet.

This separation is **not up for debate** — it was decided deliberately and reaffirmed repeatedly. Everything else about the architecture (exact module boundaries beyond this) can be proposed and changed if there's a good reason.

## 4. Domain model (in `engine/mod.rs`)

```rust
pub struct Stage {
    pub id: u32,
    pub title: String,
    pub level_hint: String,
    pub vocabulary: Vec<Vocabulary>,
    pub exercises: Vec<Exercise>,
}

pub struct Vocabulary {
    pub word: String,
    pub translation: String,
    /// Alternative correct translations for review — "salut" is "hi"
    /// but "hello" must not be wrong (D8). Same pattern as
    /// accepted_answers on exercises.
    pub accepted_translations: Vec<String>,
    pub pos: String,
    pub example: String,
}

pub enum Exercise {
    Translation { prompt: String, answer: String, accepted_answers: Vec<String> },
    MultipleChoice { prompt: String, options: Vec<String>, answer: String },
    FillBlank { prompt: String, answer: String, accepted_answers: Vec<String> },
}

pub enum Grade { Correct, CorrectWithHint(String), Incorrect }
```

Engine API: `Exercise::prompt()`, `Exercise::answer()`, `Exercise::accepted_answers()`, `Exercise::grade(attempt) -> Grade` and `Exercise::is_correct(attempt)`; `Stage::is_completed_by(correct_count)` implementing the 80% rule with integer math via `STAGE_PASS_PERCENT`.

Grading (settled in the review-fix session, decision D1; generalized by D9): both sides go through `normalize_strict` — trim, lowercase, collapse internal whitespace, strip leading/trailing punctuation (`. ? ! , ;` and Spanish's inverted `¡ ¿`), fold apostrophes (`’` → `'`), and fold Unicode composition via a hand-written 42-entry accent table — the Latin-1 Supplement set (à á â ã ä å ç é è ê ë ì í î ï ñ ò ó ô õ ö ù ú û ü ý ÿ), the decomposable Polish letters of Latin Extended-A, ą ć ę ń ś ź ż (D10), the Romanian set, ă ș ț ş ţ (D11), the Hungarian pair, ő ű (D14), and the Turkish soft ğ (D15) — so precomposed `é` equals macOS's `e` + U+0301, and precomposed `ń` equals hand-typed `n` + U+0301: same letter, same accent, different encoding. A second, loose pass drops the combining marks, opens the œ/æ/ß ligatures and the stroked ł (D10), and folds Catalan's interpunct away (D18 — `col·legi` counts with `collegi`): an accent-only, stroke-only or dot-only mismatch is **correct**, and `grade` returns `CorrectWithHint` carrying the properly spelled form, which the session prints as `correct — watch the accents: étudiant` (or `łódź`, or `col·legi`). Letters that never fold (`ø`, `þ`, `ð`, and since D15 Turkish's `ı`) deliberately stay closed — `smør` is not `smor`, and `hayır` is not `hayir`; ł does fold, because it is the same word missing a stroke — the ß rule — and the interpunct folds for the same reason: the same word missing its required mark. `accepted_answers` (optional field on translation and fill_blank, absent in old files) lists alternative correct spellings — contractions ("I'm a student"), gendered forms ("Je suis étudiante").

No `#[derive(Serialize/Deserialize)]` here, deliberately — that would leak storage-awareness into `engine/`. The JSON-shaped mirror types live in `content/mod.rs` and get converted into these via `.into_engine()`.

## 4a. SRS domain model (in `srs/mod.rs`)

```rust
pub struct SrsState { /* BTreeMap<word, Card> — word order stable, no dupes */ }
pub struct Card    { pub box_number: u8 /* 1..=6 */, pub due: String /* YYYY-MM-DD */ }
pub struct Schedule { pub box_number: u8, pub due: String }  // returned by answer()
```

Rules (classic Leitner, all in `srs/`, all pure):
- Six boxes, intervals `BOX_INTERVALS_DAYS = [1, 2, 4, 8, 16, 32]`.
- Correct answer: promote one box (capped at 6). Wrong answer: demote to box 1.
- Next due = `date + interval(new box)` — the NEW box's interval, always.
- `introduce(words, date)`: unknown words enter at box 1, **due the same day** (a freshly completed stage is reviewable immediately); already-known words are never reset.
- `due_on(date)`: overdue plus due-today, alphabetical word order (deterministic sessions).
- Dates arrive as opaque strings; `add_days`/`valid_date` (Hinnant civil-date math, owned, no time crate) live here for the same reason `prev_day` lives in `progress/`.

Review grading reuses the engine: `session/` builds an `Exercise::Translation` per due card, passing the vocabulary entry's `accepted_translations` as the exercise's `accepted_answers` (D8), so reviews share the exact normalization table (accent hint included) with stage exercises. A card whose word vanished from the loaded content is skipped untouched (see §9).

## 5. `stages.json` content format

One file per language: `<content dir>/<lang>/stages.json` (see §7 for where content dirs are).

```json
{
  "language": "french",
  "stages": [
    {
      "id": 1,
      "title": "Greetings and Basics",
      "level_hint": "beginner",
      "vocabulary": [
        { "word": "bonjour", "translation": "hello", "pos": "interjection", "example": "Bonjour, comment ça va ?" }
      ],
      "exercises": [
        { "type": "translation", "prompt": "Je suis étudiant.", "answer": "I am a student", "accepted_answers": ["I'm a student"] },
        { "type": "multiple_choice", "prompt": "Choose the correct greeting:", "options": ["bonjour", "maison", "manger"], "answer": "bonjour" },
        { "type": "fill_blank", "prompt": "___, comment ça va ?", "answer": "Bonjour" }
      ]
    }
  ]
}
```

Rules:
- **No Arabic (or any non-English) text anywhere in this file.** Prompts, translations, examples: English. Only the target-language word/sentence itself (e.g. the French) is in the target language.
- `vocabulary` and `exercises` are **separate arrays**, never merged per-word.
- `level_hint` says `"beginner"` for stages 1–5 and `"elementary"` for stages 6–10 (the stages 6–10 wave, Nov 2026); it exists to avoid restructuring the file when higher levels are added later.
- `type` is the discriminator, exactly 3 values: `translation`, `multiple_choice`, `fill_blank`, handled by `#[serde(tag = "type", rename_all = "snake_case")]` in `content/mod.rs`.
- `accepted_answers` is optional on `translation` and `fill_blank`; absent = only `answer` counts. `accepted_translations` is the same field on vocabulary entries (D8): optional, absent = only `translation` counts; entries must be non-empty.
- All stages for a language currently live in one JSON file.

**Content validation** (settled in the review-fix session): `content::load_language` validates every file at load time and reports **all** violations at once. A file must have: at least one stage; stage ids unique and strictly ascending in file order; ≥ 1 exercise per stage (an empty stage can never be completed and would block the learner forever); multiple choice with 2–26 unique options and the answer among them; non-empty `prompt`/`answer`/`word`/`translation`; a `language` field that matches the name the file is loaded as; fill-blank prompts containing `___`; non-empty `accepted_answers` entries. `add-lang` prints the full violation list and installs nothing; `termocab check <file>` runs the same validator on any file without installing it.

Strict parse: progress accepts only `stage <id>` and `day <real YYYY-MM-DD>` lines; srs accepts only `word <w> box <1-6> due <real YYYY-MM-DD>` lines (words may contain spaces — split on the ` box ` / ` due ` markers, not whitespace); anything else is an error. Saves go through temp-file + rename.
- **Content location** (review D2, extended by D16): looked up in order — `$TERMOCAB_CONTENT_DIR` (a directory containing `<lang>/stages.json`), then `$XDG_DATA_HOME/termocab/languages` (fallback `~/.local/share/termocab/languages`), then `./languages` for development, then the courses built into the binary (D16). First source that holds the language wins; `add-lang` always installs into the XDG data location (so an installed file overrides a built-in of the same name, and `add-lang` says so). A missing language lists the directories searched and everything available (`list-langs`).
- **Built-in courses, in-memory fallback** (out-of-the-box session, D16, grown to eleven courses by D17): the shipped `languages/<lang>/stages.json` files are embedded into the binary with `include_str!` (`content::builtin_languages`), and `load_lang` falls back to them only after every directory source misses. Deliberately in-memory, not materialize-on-first-run: a fresh machine gets nothing written behind the user's back, an upgrade never leaves a stale course copy in the data dir, and the dev checkout keeps winning for contributors (a checkout's `./languages` sits ahead of the built-ins in the chain). The embedded bytes ride the exact same `parse_language` + `validate` path as a file on disk — one content gate, no second trust level — and CI pins them three ways: the content unit test parses every built-in under its own name, the binary-level tests start every course with zero setup, and `shipped_courses_validate` still checks the files the bytes came from. Discovery shipped with it: `list-langs` (names, sizes, winning source, problems flagged), the missing-language error with available languages and a did-you-mean (Levenshtein ≤ 2 over chars, plus a unique-prefix rule — hand-rolled, ~30 lines, no dependency, §6), and `--version`/`-V`.
- SRS is **classic Leitner, six boxes, intervals 1/2/4/8/16/32 days** (decided Oct 2026; SM-2 was considered and rejected for the MVP — more state, more complexity, no clear win at this scale). Correct promotes, wrong demotes to box 1, next due = today + interval(new box).
- SRS scheduling source: **vocabulary of completed stages only**, introduced lazily at box 1 due the same day. No forward scheduling of unseen material.
- **A review session with at least one answered card records an active day** — the streak stays alive through reviews, not just new stages.
- No `ncurses`/TUI in MVP — plain CLI text output only.
- Exactly 3 exercise types for MVP: translation, multiple_choice, fill_blank.
- Stage completion rule: **≥ 80% of exercises correct in one run**. A stage with 6 exercises passes at 5 correct; 4/6 fails.
- **Stages unlock in order** (review D4, the original spec's rule, now enforced): `start <lang> <n>` is allowed only when stage n is already completed (replay) or is the next uncompleted stage; anything else exits 1 with "complete stage X first".
- Saving is change-driven: a failed or aborted run writes nothing, and a passed replay on an already-recorded day rewrites nothing. Reviews always save the srs state when a card was answered, but rewrite the progress file only when the day is new.
- No placement system: starting a language always starts at Stage 1. `intermediate`/`advanced` are not CLI surface yet.
- No CEFR exposed to the user; sequential Stage number is the only level concept.
- Each Stage is sized for 10–15 minutes max.
- French is the first language; the engine stays language-agnostic.
- Grading (review D1): the normalization + `accepted_answers` rules of §4, with the accent-only mismatch counted correct plus a hint. Multiple choice accepts a letter (`b`) or the word itself.
- **Local time** (review D3): read from the system's own TZif file by `cli/time.rs` — no time crate, no libc; `$TZ` (name, absolute path, or empty = UTC) and `/etc/localtime` are honored, DST included, UTC on any parse failure. The old `TZHOURS` override is gone. Handlers take a `Clock`; tests inject fixed dates, never the wall clock.
- License: **MIT** (review D5).
- **Broken pipe** (usage-review D6): a closed stdout ends the run **silently with exit code 141** (128 + SIGPIPE), exactly what cat and git report — never a panic. Every stdout write is checked (`cli::say`, `Terminal::print -> io::Result`), an aborted session saves nothing, and EPIPE is distinguished from real write errors (which stay runtime failures, exit 1). Re-raising the actual signal would need unsafe libc calls, which §6 rules out; 141 is what the shell reports either way.
- **Shuffled stage exercises** (usage-review D7): stages present their exercises in a seeded-shuffled order by default — memorizing positions is not vocabulary. `--no-shuffle` keeps the authored order; `--seed <n>` pins the order (reproducible runs, tests, comparisons). The permutation is a hand-written Fisher–Yates over SplitMix64 (no `rand`, §6); the seed defaults to OS entropy (nanos ^ pid) resolved at the CLI edge, like the clock. Reviews are deliberately **not** shuffled: due-date order is the documented deterministic order.
- **Alternative translations in review** (usage-review D8): vocabulary entries take an optional `accepted_translations` array, the exact pattern of `accepted_answers` on exercises — a review of `salut` accepts both "hi" and "hello", through the same forgiving grading (case, accents, punctuation) as the primary translation. `list-words` shows the alternatives as `hi (also: hello)`.
- **Color** (usage-review): session feedback is green (correct) / red (not quite) **only when stdout is a terminal** and `$NO_COLOR` is unset or empty (no-color.org, to the letter — empty does not count as set). Piped output never contains escape codes. Decided at the CLI edge (`std::io::IsTerminal`, no dependency), passed into the session as a value.
- **Language-agnostic normalization** (second-language session, D9): the accent table is the accented-letter set of the whole Latin-1 Supplement — 27 lowercase entries covering Western Europe (Spanish, German, Italian, Portuguese, Catalan, Icelandic…), not a French dialect; `¡` and `¿` join the edge-punctuation set (`hola` is `¡Hola!`); `ß` opens to `ss` in the loose pass exactly like `œ` → `oe`. Letters that are letters in their own right (`ø`, `þ`, `ð`) never fold. When a language outside the set arrives (Polish, Romanian, …), extend the table with Latin Extended-A entries — same pattern, still no Unicode-normalization dependency.
- **Latin Extended-A, the Polish set** (fifth-language session, D10): the D9 prediction, executed. The seven decomposable Polish letters (ą ć ę ń ś ź ż) joined `ACCENTED` as base + combining mark — ogonek U+0328, acute U+0301, dot above U+0307, all inside the loose pass's existing combining range, so the loose pass needed no change at all. ł, which has no Unicode decomposition, joined `ß`'s loose-only opening rule as a new `OPEN_LETTERS` table beside the ligatures: `łódź` counts with `lodz` as the hint, exactly like `straße` with `strasse`. ø þ ð stay closed (D9 stands). This decision also predicted how Romanian would land — ă via `ACCENTED`, ș and ț via `OPEN_LETTERS` — and the prediction was half wrong; see D11 for the corrected outcome. Still no Unicode-normalization dependency.
- **Latin Extended-A/B, the Romanian set** (sixth-language session, D11): the second live test of the extension path, and the outcome was smaller than predicted. ă joined `ACCENTED` as expected (a + breve), but ș and ț turned out to decompose too (s/t + combining comma below, U+0326 — Extended-B included), so they joined `ACCENTED` beside the Polish letters instead of following ł into `OPEN_LETTERS`; the legacy cedilla spellings ş ţ (s/t + cedilla, the mark ç already carries) joined as well, so both historical encodings of the same two letters grade the same way — `şarpe` counts with `șarpe` as the hint. `OPEN_LETTERS` still holds just ł. The change is purely additive: no other shipped course contains a new letter, so nothing shifted under the other five. Still no Unicode-normalization dependency.
- **Portuguese, the seventh language** (seventh-language session, D12): pure content — the first course since Italian that changed nothing in the engine, which was the point of choosing it: D9 named Portuguese as its reason for widening the table, and the language arrived to collect. Every diacritic in real content (ã õ ç á é í ó ú ê ô à) rides the existing table — â is the one Portuguese mark left out, no beginner-frequency word carrying it — and the crase à, a preposition and feminine article fused into one grave-accented letter, folds exactly like French's grave: `a` counts with `à` as the hint. The course is explicitly **Brazilian Portuguese** — the first variant decision in the project (`você` over `tu`, `tchau`, `Meu nome é`, `Vejo você amanhã`, `obrigado`/`obrigada` both accepted). Nouns carry gendered articles like German's and Italian's; stage 3's contraction drills are the Portuguese signature (crase `às` before hours, `à` before feminine places, `ao`/`na`/`no` in the sentences); stage 4 keeps querer/poder + the bare infinitive.
- **Swedish, the eighth language** (eighth-language session, D13): pure content again — the last clean zero-change candidate inside the D9 table, chosen for exactly that reason: every remaining candidate forces an engine change (Hungarian and its double acute, Catalan and its interpunct, Dutch and its ĳ ligature, Turkish/Icelandic and their letters-in-their-own-right), so this was the last chance to collect a free wave. å (a + ring above U+030A), ä (a + diaeresis) and ö (o + diaeresis) were all in the table from D9 day one; `atta` counts with `åtta` as the hint, `forsta` with `förstå`. The noun convention inverts the German one: Swedish dictionaries list the indefinite article, so the course's nouns carry en/ett (`en man`, `ett namn` — the one neuter noun among the family set, with `ett` doubling as the number one), the stage-2 drill blanks the indefinite article (the gender drill: `___ barn sover nu.` wants `ett`), and the definite article — enclitic, like Romanian's — rides at stage 3 as the signature (`Veck___ har sju dagar.` wants `an`, `Timm___ har sextio minuter.` wants `en`), with the definite forms alive throughout the sentences (`tidningen`, `pojken`, `kaffet`). The modal drill is unchanged in shape: vilja/kunna + the bare infinitive (`Jag vill ___ en kaffe.` wants `dricka`).
- **Hungarian, the ninth language** (ninth-language session, D14): the third engine extension, and the smallest — two entries, exactly the shape the roadmap predicted when it called Hungarian the gentlest table extension. ő (o + double acute U+030B) and ű (u + double acute) are Latin Extended-A letters that decompose like any accented letter, so they joined `ACCENTED` beside the Polish (D10) and Romanian (D11) sets; the double acute sits inside the loose pass's existing combining range, so nothing else moved — `no` counts with `nő` as the hint, `konnyu` with `könnyű`, and ő and ö stay distinct letters (`fű` is never `fő`). `OPEN_LETTERS` still holds just ł. The course conventions: nouns are bare like Polish's (Hungarian articles carry no gender, and the dictionary form is the noun alone), the stage-2 article drill is the a/az alternation (a before consonants, az before vowels — predictable from the noun's first letter, so the drill is the alternation itself), stage 3's signature is the plural suffix with its linking vowel blanked (the linking vowel IS the vowel harmony: `ember___` wants `ek`, `férfi___` wants `ak`, `fiú___` wants `k`), stage 4's modal drill is akarni/szeretni/tudni + the -ni infinitive blanked at the end where Hungarian puts it, and `accepted_translations` carries the homonyms (hét seven/week, nap day/sun, óra hour/clock) so both meanings of one spelling review correctly.
- **Turkish, the tenth language** (tenth-language session, D15): the fourth engine extension, and the first that arrived as two questions instead of one — the roadmap called Turkish (or Icelandic) the language that would reopen the letters-in-their-own-right question, and the reopening had two halves with opposite answers. The soft ğ (g + breve U+0306 — the very mark Romanian's ă carries, D11) decomposes like any accented letter, so it joined `ACCENTED` beside the Polish, Romanian and Hungarian sets: `soguk` counts with `soğuk` as the hint. ş needed no entry at all — the cedilla spelling D11 kept for Romanian's history is Turkish's own letter, so `kardes` counts with `kardeş` through a table entry that already existed: the first time a language's letter was already on file for another language's sake, the prediction track record's strangest hit. The other half went the opposite way: dotless ı has no decomposition and does not open — ı and i are different vowels in their own right, exactly what ø is to o — so ı joined the closed club with ø þ ð (D9) and `OPEN_LETTERS` gained nothing: `hayir` is wrong for `hayır`, never hinted, and the e2e test pins the stage completing at 7/8 with the closed miss counting against the pass bar while the hinted folds count toward it. Capital İ needed no entry either (`to_lowercase` leaves i + U+0307 and the loose pass drops the dot, so `istanbul` counts with `İstanbul` as the hint), and it exposed the one asymmetry the Unicode default case mapping leaves — capital I lowercases to dotted i, so `HAYIR` typed with an ASCII capital does not round-trip to `hayır`, the classic Turkish-I problem; the engine is language-agnostic (`normalize_strict` never knows which language it holds), so the edge is documented, not special-cased. One authoring rule follows for content: answers never carry capital İ, because its lowercase residue would make a correctly spelled `iyi` take a false hint against an authored `İyi`. The course conventions: nouns are bare like Polish's and Hungarian's (Turkish's only article is indefinite), the stage-2 drill is bir itself — the word that is both "a" and "one", the Swedish ett doubling (`Bu ___ kız` wants bir) — stage 3's signature is the plural suffix blanked, the vowel harmony made visible exactly like Hungarian's linking vowel (`Kız___` wants lar, `Aile___` wants ler — the back and front vowels picking their own suffix), stage 4's modal drill is istemek + infinitive with -mek/-mak blanked mid-sentence where SOV puts it (`Kahve iç___ istiyorum` wants mek), and `accepted_translations` carries the homonyms (yemek to eat/food, ay month/moon, kız girl/daughter, kardeş sibling/brother/sister) so both meanings of one spelling review correctly. Every Turkish letter is alive in real content (â in hikâye, ç in üç, ğ in günaydın, ı in hayır, ö in görmek, ş in kardeş, ü in lütfen).
- **The stages 6–10 wave convention** (stages 6–10 session, Nov 2026): content, not engine — but a convention worth naming so the next wave matches it. Every course grows through the same five-stage elementary skeleton (Food and Drink / Home and Places / Daily Routine and Weather / Shopping and Travel / Yesterday and Tomorrow, `level_hint: "elementary"`, ~16 words and ~44 exercises per stage), while each course's stages 6–10 keep that course's own drill identity — one signature grammar point per stage, always the natural continuation of its stages 1–5 signature (the article/gender/harmony/definite-article drills return on new vocabulary, and every course's stage 10 introduces its past or future construction). Vocabulary stays in the course's own dictionary convention (articles where the course carries them, bare where it does not); every stage's fill-blank answers must be inferable from the prompt alone (meals by their clock, counting sequences, sums, unambiguous contexts — never a blank two course words could fill); no duplicate vocabulary words course-wide, since the srs keys on the word itself.
- **Icelandic, the eleventh language** (eleventh-language session, D17): pure content — and the purest yet, the first course since Portuguese and Swedish to change nothing in the engine, and the first of those to arrive with **no new question to answer at all**: D9's table held every letter the language carries on the day it was written. The acutes á é í ó ú ý and the ö ride the Latin-1 `ACCENTED` entries D9 shipped for exactly this coverage; æ rides `LIGATURES` beside the œ it shares with French (`hae` counts with `hæ` as the hint); and þ and ð take the closed-club answer D9 ruled on day one — letters in their own right, never hinted — which D15's ı had just reaffirmed, so the roadmap's prediction ("Icelandic would collect the closed letters the ı precedent now predicts") landed whole: `thu` is wrong for `þú`, `godur` is wrong for `góður`, while the foldable letters around a closed one still fold (`þu` counts with `þú` as the hint — the split pinned in a single word). No authoring rule either: the D15 capital-İ asymmetry has no Icelandic analogue, Þ Ð Æ and the acute capitals all round-trip through `to_lowercase` cleanly. The course conventions: nouns bare like Polish's and Hungarian's (no indefinite article, the dictionary form is the nominative singular alone), the stage-2 drill is the three-gender pronoun hann/hún/það (the identification slot's edition — Icelandic's three noun genders surface through the pronouns), stage 3's signature is the enclitic definite article blanked at the end of the noun (`Hest___` wants `urinn`, the Romanian/Swedish slot), stage 4's modal drill is vilja/þurfa + að + infinitive with the dictionary form carrying the particle — the Romanian `a citi` convention, Icelandic edition — stage 7's signature is the í/á locative split (the German in/auf and Swedish i/på slot), stage 8's is the klæða mig/sig reflexive plus the weather sentences, and stage 10's is the weak past -ði/-i blanked (`Ég tala___ í gær` wants `ði` — the closed ð living inside the past suffix) beside the ætla að future. `accepted_translations` carries the genuine homonyms: hæ hi/bye, banki bank/bench, dýr expensive/dear/animal.
- **Catalan, the twelfth language** (twelfth-language session, D18): the fifth engine extension, one character wide, and the first entry that is not a letter — `FOLDED_MARKS`, a new table of marks that fold away in the loose pass without being combining diacritics, holding Catalan's interpunct (`·`, U+00B7, the punt volat of `col·legi`). The question the roadmap held open — decoration like ¡ ¿, or meaningful like a letter — answered *neither*: not decoration, because ¡ and ¿ only ever wrap an utterance while the dot sits inside the word and its absence is a genuine misspelling (`collegi` is wrong in Catalan, the IEC norm requires the mark between certain geminates), so it cannot be stripped in the strict pass where a misspelling must not pass scot-free; not a letter in its own right, because it has no sound and no place in the alphabet — it separates `l·l` from `ll`, a spelling convention, not a phoneme — so the closed club ø þ ð ı gains nothing. It takes the tier ł built (D10): the dot survives the strict pass (a correctly typed `col·legi` is a full match) and folds in the loose pass, so `collegi` counts with `col·legi` as the hint — `lodz` with `łódź`'s rule. Every other Catalan letter was already on file from D9 (à è é í ï ó ò ú ç — the ç French shipped with); the change is purely additive (no other shipped course contains the character, the D14 rule). The ASCII hyphen fallback (`col-legi`) stays a miss — folding internal hyphens would touch every shipped course — and ŀ (U+0140, l + middle dot) stays off `ACCENTED` despite its canonical decomposition: no modern text carries it, the Portuguese â rule one tier stricter. The course conventions: standard (IEC) Catalan as spoken in Catalonia (the second variant decision, after D12's Brazilian Portuguese), nouns with gendered articles plus the apostrophe elision (l'home, l'aigua — carried, not drilled), stage 3's mandatory contraction drill (al/del — the crase's sister), voler/poder + infinitive with ser/estar contrasted, the agradar flip and tinc gana/set at stage 6, hi ha at stage 7 (the slot Portuguese gave tem), the em/es/ens reflexive at stage 8, Quant costa/costen at stage 9, and the go-past at stage 10 (Ahir vaig menjar against Demà vaig a menjar — anar + infinitive grammaticalized as the simple past, drilled in a minimal pair), with `accepted_translations` on the homonyms el temps weather/time, el col·legi school/college, la pel·lícula film/movie, la tardor autumn/fall, la feina work/job.
- **Dutch, the thirteenth language** (thirteenth-language session, D19): the sixth engine extension, one entry wide, and the answer to the last question the roadmap had named — where does ĳ live, `LIGATURES` or `OPEN_LETTERS`? With the ligatures. It is one (the Unicode name says so: LATIN SMALL LIGATURE IJ), and its opening is the two-letter sequence it spells — ĳ → "ij", exactly the œ → oe and æ → ae shape — while `OPEN_LETTERS` holds letters in their own right opening to a single plain letter (ł → l), which ĳ is not: the ligature has no phoneme of its own, it is typography for the ij digraph the language writes with two letters everywhere. So `LIGATURES` grew to four (œ æ ß ĳ) and `OPEN_LETTERS` still holds just ł; the closed club ø þ ð ı gains nothing — no Dutch letter is a letter in its own right the way those are, and the change is purely additive (the D14 rule). The mechanics: the strict pass leaves ĳ alone (a correctly ligatured "ĳsselmeer" is a full match — the ligature has a compatibility decomposition, not a canonical one, so it cannot ride `ACCENTED`'s strict machinery), the loose pass opens it to the two letters, so modern spelling — what every modern Dutch text types — counts with the ligature form as the hint ("het IJsselmeer" for "het Ĳsselmeer", the ß/straße tier), and the old-orthography spelling folds the same way in reverse ("mĳn" for "mijn"). The y of the schoolbook shorthand is no spelling of any word — the fold is exactly i+j, never y — so "myn" is wrong for "mijn", never hinted, the same counterweight the Catalan hyphen and the closed letters carry. Capital Ĳ needs no entry and no authoring rule: `to_lowercase` maps it to ĳ (single char, no D15-style residue), so an all-caps answer grades strict with no hint at all. Every other character in the course was already on file from D9: the é of één — the one Dutch word where an accent does grammar, separating the number one from the article een — and the trema ë of ideeën, the diaeresis with its separating job. The course conventions: standard Dutch as spoken in the Netherlands (the third variant decision, after D12's Brazilian Portuguese and D18's IEC Catalan), nouns with their de/het articles (the German convention returns, Dutch edition — two genders, de common / het neuter, pos "noun (de)"/"noun (het)"), the stage-2 drill the de/het article blank (the German-article slot) beside the family-relation blanks, stage 4's modal drill willen/kunnen/moeten + the bare infinitive blanked at the END where SOV puts it (the German slot, Dutch edition), stage 6's signature the hou van flip with honger/dorst (the agradar slot), stage 7's er is/er zijn (the hi ha slot) with the diminutive -je alive in real content (meisje from stage 2, huisje/boekje/stadje drilled), stage 8's separable verbs blanked at the end where the prefix lives (Ik sta om zeven uur ___ op — the slot Polish's ogonek never drilled), stage 9's hoeveel kost/kosten (the Quant costa slot) and het Ĳsselmeer as the one real-content word that exercises D19 — exactly the "barely exercises it" the roadmap predicted, since modern Dutch types the two-letter ij — and stage 10's ge- participle past drilled against the gaan future in a minimal pair (Gisteren heb ik een boek gelezen / Morgen ga ik een boek lezen — the Catalan go-past/go-future pair, Dutch edition), with `accepted_translations` carrying the near-homonyms (de reis trip/journey, de stad city/town, de fiets bicycle/bike, gezellig cosy/cozy/fun/sociable).
- CLI is git-style direct subcommands only, named **start** (with `--no-shuffle`/`--seed <n>`, D7), **review**, **list-words**, **progress**, **streak**, **stats** (usage-review: boxes, 14-day review load and activity as plain-text Unicode sparklines, no color), **add-lang** (with `--force` to replace an existing language), **check**, **help**. ## 9. Remaining open questions

- Whether `content/`'s wire types stay permanently separate from `engine/`'s domain types. Current answer: they stay separate — don't collapse without a reason tied to §3. (The built-in embedding of D16 lives in `content/` too: it is compile-time storage, so the module's one place that knows a storage format is still the only one.)
- Orphan srs cards: a card whose word disappears from the content is skipped at review time and left in place forever. Fine at this scale; the honest fix is either pruning orphans on load or a `termocab` maintenance verb, to be decided when real content churn exists.
- Review session caps: a learner returning after weeks gets every overdue card in one sitting. Capping session size (e.g. newest-due-first, N per session) is a real UX question once there is enough content to matter.
- `cli/time.rs` covers `$TZ` names, absolute paths, empty-TZ and `/etc/localtime`; a POSIX TZ *string* (e.g. `EST5EDT,M3.2.0`) that has no zoneinfo file falls back to UTC. Fine until someone reports it.
- Publishing to crates.io: `cargo install termocab` is now meaningful (D16 made a published binary self-sufficient), but publishing brings versioning/release-process questions (who cuts releases, what a semver guarantee means for course content) that are not settled.

## 11. Code quality bar

Every change should hold up against: Separation of Concerns, Single Responsibility, Low Coupling, High Cohesion, Abstraction, Encapsulation, Modularity, Error Handling, Testability, Maintainability. `cargo build` must stay warning-free and `cargo test` green — at the tip. CI (`.github/workflows/ci.yml`) enforces `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` and `cargo build --release` on ubuntu-latest and macos-latest, on every push and PR — it is the review gate. The project owner reviews and tests changes personally — keep code clear and readable, not just functionally correct. Work in small, focused commits, since review happens through git history. The established pattern is one commit per layer (domain → storage → session → cli → docs, see the MVP, srs and review-fix waves in the log): an intermediate layer commit naturally carries dead-code warnings until the next commit wires it into the CLI, and `cargo test` stays green throughout — that is accepted; what is never accepted is a warning at the tip.

## 12. Build & run

```
cargo build          # warning-free
cargo test           # 112 unit + 41 binary-level integration tests
cargo run            # prints usage, with the built-in courses named
cargo run -- list-langs         # every language this checkout sees, and where from
cargo run -- start french       # play the next stage (shuffled by default, D7)
cargo run -- start spanish      # the second course, same engine (D9)
cargo run -- start german       # the third course: articles, umlauts, ß
cargo run -- start italian      # the fourth course: elisions, grave + acute
cargo run -- start polish       # the fifth course: the D10 wave, ogoneks + the stroke
cargo run -- start romanian     # the sixth course: the D11 wave, enclitic articles, ă â î ș ț
cargo run -- start portuguese   # the seventh course: the zero-change wave, crase à, tildes ã õ, querer + infinitive
cargo run -- start swedish     # the eighth course: the last zero-change wave, en/ett, the definite suffix, å ä ö
cargo run -- start hungarian    # the ninth course: the D14 wave, the double acute ő ű, a/az, the plural suffix
cargo run -- start turkish      # the tenth course: the D15 wave, the soft ğ and the closed ı, bir, the vowel-harmony plural
cargo run -- start icelandic    # the eleventh course: the zero-change payoff, þ ð closed, æ a ligature, the enclitic article
cargo run -- start catalan      # the twelfth course: the interpunct fold (col·legi/collegi), the al/del contractions, the go-past
cargo run -- start dutch        # the thirteenth course: the ĳ ligature fold (Ĳsselmeer/IJsselmeer), de/het, the separable verbs
cargo run -- start --no-shuffle french 1   # authored exercise order
cargo run -- start --seed 42 french 1      # reproducible order
cargo run -- review italian     # spaced-repetition review of due words
cargo run -- progress italian   # per-stage checkboxes + streak + due count
cargo run -- stats italian      # boxes + 14-day charts as sparklines
cargo run -- list-words italian
cargo run -- streak italian
cargo run -- add-lang italian ./italian.json     # installs into the XDG data dir
cargo run -- add-lang --force italian ./new.json # replaces an installed language
cargo run -- check languages/italian/stages.json # validate a shipped course
```

An installed binary needs none of this: `cargo install --path .`, then
`termocab start french` works from any directory — the courses are built
in (D16), and `termocab list-langs` shows what is available.
