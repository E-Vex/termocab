# termocab

**Language learning for terminal enthusiasts.**

A terminal-native vocabulary trainer: staged lessons, spaced-repetition
reviews, streaks — fully offline, fully local, no account, no network.
Plain text everywhere: content is JSON, your progress is a file you can
`cat`. UX modeled on git — direct subcommands, no menus.

Thirteen courses ship today: French (fifteen stages, 233 words, 617
exercises), Spanish (fifteen stages, 233 words, 637 exercises), German
(fifteen stages, 233 words, 656 exercises — nouns with their articles,
modal-verb drills, umlauts and the sharp s), Italian (fifteen stages,
233 words, 658 exercises — articles with their elisions, modal-verb
drills, the grave and the acute accents), Polish (fifteen stages,
233 words, 658 exercises — bare nouns, "to jest" drills, want/like +
infinitive drills, every letter ą ć ę ł ń ó ś ź ż alive in real
content), Romanian (fifteen stages, 233 words, 658 exercises — the
enclitic definite article blanked where it lives, at the end of the
noun, can + infinitive drills, every letter ă â î ș ț alive in real
content), Portuguese (fifteen stages, 233 words, 658 exercises —
Brazilian Portuguese, nouns with their gendered articles, the crase

## Releases & versioning

Releases are cut by tag (D20 in `HANDOFF.md`, the process in
`RELEASE.md`): the owner pushes `vX.Y.Z`, and the Release workflow verifies
the tag — fmt, clippy, tests, release build, publish dry-run — then
publishes the crate to crates.io and attaches release binaries (Linux and
macOS) to the GitHub Release. `cargo install termocab` becomes the
one-line install at the first tagged release.

One version number covers the engine, the CLI and the embedded courses
together — they ship as one binary. SemVer with a content contract: stage
ids are append-only, review state only ever orphans (skipped at review,
never an error), and grading plus the CLI surface only grow — additive
content (a new course, a new stage wave) is a MINOR bump, anything that
could strand existing learner state is a MAJOR bump. Release history:
`CHANGELOG.md`.

## Install & run

```
cargo install termocab     # once the first release is tagged (Releases above)
cargo install --path .     # or, from a checkout
cargo install --git https://github.com/E-Vex/termocab
termocab start french      # the thirteen shipped courses are built into the binary
termocab list-langs        # every language available on this machine
```

`cargo install` puts the binary in `~/.cargo/bin` — if you then get
`termocab: command not found`, that directory is not on your `$PATH`
(rustup normally adds it; `ls ~/.cargo/bin` shows what is there).

To try it without installing:

```
cargo run -- start french                              # from a checkout
cargo build --release && ./target/release/termocab start french
                                                        # works from any directory
```

The thirteen shipped courses are compiled into the binary, so a fresh
install works with zero setup, from any directory. Content is looked
up in this order (first hit wins):

1. `$TERMOCAB_CONTENT_DIR` — a directory containing `<lang>/stages.json`
2. `$XDG_DATA_HOME/termocab/languages`, or `~/.local/share/termocab/languages`
   (this is where `add-lang` installs — installing a language that also
   ships built-in, e.g. `add-lang french my-french.json`, replaces the
   built-in copy for that name)
3. `./languages` — development convenience, so `cargo run` works from a
   checkout
4. the courses built into the binary

`termocab list-langs` shows every available language, its size and where
each one comes from.

Progress and review state live under `$XDG_CONFIG_HOME/termocab`
(fallback `~/.config/termocab`), one plain-text file per language.

## Commands

```
termocab start [--no-shuffle|--seed <n>] <lang> [stage]
                              run the next uncompleted stage (or a specific one);
                              exercises shuffle by default
termocab review <lang>            review due vocabulary with spaced repetition
termocab list-words <lang>        list all vocabulary in a language's stages
termocab list-langs               list available languages and where each comes from
termocab progress <lang>          show completed stages, streak and due reviews
termocab streak <lang>            print the current streak in days
termocab stats <lang>             words, Leitner boxes and 14-day charts as sparklines
termocab add-lang [--force] <lang> <file>  install a stages.json file as a language
termocab check <file>             validate a stages.json file without installing it
termocab --version                print the version
termocab help                     show this help
```

Exit codes follow git: 0 success, 1 runtime failure, 2 usage error —
and a closed stdout (a broken pipe, `termocab list-words french |
head`) ends quietly with 141, exactly like cat and git.
Stages unlock in order (a completed stage can be replayed anytime).
A stage is passed at ≥ 80% correct in one run; reviews use Leitner boxes
with 1/2/4/8/16/32-day intervals.

Feedback prints green for correct and red for not-quite when stdout is
a terminal; pipes and files always stay plain, and `$NO_COLOR` disables
color everywhere (no-color.org).

## Content format

One `stages.json` per language — see `languages/swedish/stages.json`
or `languages/italian/stages.json` for full examples and `HANDOFF.md`
§5 for the rules. Quick sketch:

```json
{
  "language": "french",
  "stages": [
    {
      "id": 1, "title": "Greetings and Basics", "level_hint": "beginner",
      "vocabulary": [
        { "word": "bonjour", "translation": "hello",
          "accepted_translations": ["hi", "good morning"],
          "pos": "interjection", "example": "Bonjour, comment ça va ?" }
      ],
      "exercises": [
        { "type": "translation", "prompt": "bonjour", "answer": "hello" },
        { "type": "translation", "prompt": "Je suis étudiant.", "answer": "I am a student.",
          "accepted_answers": ["I'm a student"] },
        { "type": "multiple_choice", "prompt": "Choose the word for 'hello':",
          "options": ["bonjour", "au revoir", "merci", "non"], "answer": "bonjour" },
        { "type": "fill_blank", "prompt": "___, comment ça va ?", "answer": "Bonjour" }
      ]
    }
  ]
}
```

Grading forgives case, whitespace, edge punctuation (including
Spanish's inverted ¿ ¡), missing accents (an accent-only miss counts
as correct and shows the accented form — Italian's grave and acute
accents fold the same way, so `perche` counts with `perché` as the
hint — and German's `ß` opens like a ligature, so `strasse` counts
with `Straße` as the hint); Polish folds the same way one table
further out in Latin Extended-A: `dziekuje` counts with `dziękuję`
as the hint, and the stroked `ł` opens exactly like `ß`, so `lodz`
counts with `łódź`; Romanian folds one step further still — `ă`,
`ș` and `ț` decompose like any accent (so `multumesc` counts with
`mulțumesc` as the hint) and the legacy cedilla spellings `ş` `ţ`
count with the standard `ș` `ț` as the hint; and Portuguese needed
no new rule at all — D9's Latin-1 set was widened for exactly these
letters, so `irmao` counts with `irmão`, `maca` with `maçã`, `voce`
with `você`, and even the crase forgives: `a` counts with `à` as
the hint; and Swedish collected the last free wave — å ä ö were in
the D9 table from the start, so `atta` counts with `åtta`, `gar`
with `går`, and `forsta` with `förstå` as the hint; and Hungarian
took the third table extension — the double-acute letters ő ű
decompose like any accent, so `no` counts with `nő`, `ketto` with
`kettő`, and `konnyu` with `könnyű` as the hint; and Turkish took
the fourth, the first that split in two: the soft ğ folds like any
accent (`soguk` counts with `soğuk`, and `kardes` with `kardeş`
through an entry that was already on file for Romanian), while
dotless ı stays closed the way ø does — `hayir` is wrong for
`hayır`, never hinted: two different vowels, not one word spelled
twice; and Icelandic collected the whole payoff with nothing new at
all — the acutes and the ö were in the D9 table from the start
(`ja` counts with `já`, `tolva` with `tölva` as the hint), æ rides
the ligature fold the table shipped with (`hae` counts with `hæ`
as the hint), and þ and ð stay closed exactly as D9 ruled on day
one, the ı precedent reaffirmed: `godur` is wrong for `góður`,
never hinted — while the letters around a closed one still fold,
so `þu` counts with `þú` and `goður` with `góður` as the hint; and
Catalan answered the punctuation question its course had been
chosen to ask — the punt volat folds like ł's stroke, so `collegi`
counts with `col·legi` as the hint and `pellicula` with
`pel·lícula`, while the hyphen some typists write instead
(`col-legi`) stays a miss, and every accent rides the table D9
shipped with Catalan's name already on it: `gracies` counts with
`gràcies`, `felic` with `feliç`, `raim` with `raïm` as the hint; and
Dutch answered the ligature question its course had been chosen to
ask — ĳ opens like œ
and æ to the two letters it spells, so `het IJsselmeer` counts with
`het Ĳsselmeer` and `mĳn` with `mijn` as the hint, the schoolbook y of
`myn` stays a miss for `mijn`, and every accent was already on file:
`een` counts with `één` — the one Dutch word where the accent does
grammar, separating the number from the article — and the trema folds
like any diaeresis, `de ideeen` with `de ideeën` as the hint.
`accepted_answers` lists alternative correct spellings, and
`accepted_translations` on a vocabulary entry lists alternative correct
translations a review will accept — reviewing `salut` with "hello" is
right, not wrong. Validate a file before installing it:

```
termocab check my-language.json
termocab add-lang my-language my-language.json
```

## Status

Early and actively developed. Rust (no CLI framework, no time library —
stdlib plus serde only), Linux and macOS, MIT licensed. The architecture
and every settled decision are documented in `HANDOFF.md`.

## Development

```
cargo build            # warning-free
cargo test             # unit + binary-level integration tests
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

CI runs all of the above on ubuntu and macOS. The release process — who
cuts releases, what semver means for course content, the owner's go-live
checklist — is documented in `RELEASE.md` (D20).
